# Passation M5-10 : le service de la Forge et les outils du Forgeron

Vague C de M5 (`design/M5.md` §5.4, §6.1 à §6.3, §8.3, fiche M5-10 au §17.2). La Forge existe : **`ForgeService`**
(le pipeline d'une source à un module chargeable, le banc sur le vrai hôte, le cache des versions construites,
l'arsenal, la revue) et les **cinq outils du Forgeron** (`module_list`, `module_read`, `game_ids`, `forge_test`,
`forge_save`). Rien n'est encore branché au serveur : `createForge` rend toujours `DisabledForge("not wired yet")`
jusqu'à M5-21. **En cas de contradiction avec `M5.md`, le code et cette passation font foi** (`M5.md` a un encart
« Passation M5-10 » et ses §5.3 et §8.3 renvoient ici).

## Le service (`ForgeService`)

```kotlin
class ForgeService(
    services: NarratorServices,
    store: ArsenalStore = ArsenalStore(services.dataDir.resolve(ARSENAL_DIR), services.clock),   // world/narrator2/forge
    dryCheck: suspend (tool: String, args: JsonObject) -> ToolResult? = engineDryCheck(services),
    newCompiler: (onStuck: (String, Instant) -> Unit) -> EcjCompiler = { EcjCompiler(onStuck = it) },
) : Forge {
    val lostThreads: LostThreads                 // celui de toute la Forge : banc et moteur
    fun start(scope: CoroutineScope = services.scope): Job   // une fois ; le premier appel le fait sinon
    override fun noteFault(name: String, version: Int, fault: String)
    companion object {
        const val ARSENAL_DIR = "forge"; const val AWAITING_APPROVAL = "awaiting_approval"; const val NO_SCENARIO = "…"
        const val TESTED, REFUSED, SAVED, COMPILED, BROKEN, APPROVED, REJECTED, STUCK   // décisions forge
        const val BENCH_THREAD = "narrator2-bench-module"; const val LINE_WAIT_MS = 1_000L
        val REPORT_CHARS: Int                    // 5 981 = 6 000 − "Invalid arguments: "
        fun engineDryCheck(services): suspend (String, JsonObject) -> ToolResult?
    }
}
```

- **Le pipeline** (§5.4) : 1. nom (`Manifest.nameProblem`), source vide, plus de 48 000 caractères, ligne `package`
  (`line 2: a module has no package: delete this line`) ; 2. `EcjCompiler.compile(Manifest.mainClass(name), source,
  label = name)` ; 3-4. `BytecodeGuard().check` ; 5. `Manifest.read` ; 6. `Instrumenter.rewrite` ; 7. le banc ;
  8. `ArsenalStore.save`. `test` fait 1 à 7, `save` 1 à 8 (et veut un scénario **avant** le banc), `build` 1 à 6 ou le cache.
- **`build(name, version)`** : `version` nulle → la dernière `ready` ; sinon, ou sans version `ready`, la version
  demandée (ou la dernière) et son refus : inconnue `Invalid arguments: no module x in the arsenal`,
  `Invalid arguments: x has no version 3 (its versions: 1, 2)` ; `pending` →
  `DENIED (awaiting_approval): x v2 waits for an operator's approval (/narrator forge approve x 2)` ; `rejected` →
  `Invalid arguments: x v2 was rejected by an operator: deploy another version` ; `broken` →
  `FAILED: x v2 is broken: <cause>`. Puis le cache, sinon la source relue et vérifiée contre son empreinte
  (`ArsenalStore.checkedSource`), puis les étapes 1 à 6 ; une version qui ne se construit plus devient `broken`
  (`markBroken`, cause `it no longer builds against the SDK of now: Beacon.java:10:20: The method shout(String) is
  undefined for the type Acts`), décision `forge broken`, et `FAILED: … is broken: …`. Le `Built` rendu porte l'entrée
  **du moment** (statut, faute), les classes du cache.
- **Le cache** : 64 versions (`ForgeLimits.BUILD_CACHE`), la moins récemment servie part la première ; clé = nom,
  version, empreinte, `Sdk.VERSION` ; rempli par `build`, par le démarrage (modules de départ et versions forgées) et
  **par `save`** (le premier déploiement d'une version qu'on vient de sauver ne recompile pas).
- **Le démarrage** (`start`, ou le premier appel) : `store.load()` ; `ModuleHost.preload()` sur `Dispatchers.IO` ;
  chaque module de départ du jar construit (étapes 1 à 6, sans banc) puis `addBuiltIn` (un échec : `ERROR`, pas listé) ;
  puis, **en tâche de fond**, chaque version forgée `ready` ou `pending`, de la plus récente à la plus ancienne, une à
  la fois (`broken` si elle ne se construit plus ; décision `compiled` sinon). Chaque appel attend la fin de la
  lecture et des modules de départ, pas celle de la vérification des versions forgées (une construction de
  déploiement attend au plus une compilation dans la file du compilateur).
- **Indisponible** (`available` faux, `unavailableReason`) : arsenal illisible au démarrage, compilateur bloqué (`the
  compiler is stuck since 21:04:10: …`), trop de fils des modules perdus (`lostThreads.stuck`), serveur qui s'arrête.
  Chaque appel lève alors `DENIED (forge_off): the Forge is unavailable: <raison>` ; décision `forge stuck` (sujet
  `compiler` ou `module threads`).
- **Erreurs qui ne sont pas de la source** : compilation de plus de 10 s → `FAILED: the compilation of x took too long
  (over 10 s): write a simpler source` ; compilateur arrêté → `FAILED: the server is stopping` ; réécriture qui lève
  autre chose que `RewriteRefused`, ou hôte du banc qui ne charge pas → `FAILED: … a defect of the mod, not of the
  module` (et un `ERROR` avec la pile).
- **`stop()`** : le compilateur s'arrête, le démarrage et les bancs en cours sont annulés, plus rien ne démarre ; ne
  bloque jamais.
- **Fils** : rien de lourd sur le fil de l'appelant : ECJ sur son fil, garde, manifeste et réécriture sur
  `Dispatchers.Default`, l'hôte du banc créé sur `Dispatchers.IO`, le banc sur `Dispatchers.IO` (M5-08) et un fil
  des modules à lui (`narrator2-bench-module-N`, `ModuleThreads` neuf à chaque banc, fermé après, partageant
  `lostThreads`), les fichiers sur `Dispatchers.IO` (M5-09). Seules les vérifications à sec (les `check` des outils,
  courts) tournent dans le contexte de l'appelant.

### Les décisions `forge` (§15)

`tested` (chaque test et chaque sauvegarde examinée ; `refused` à la place quand la garde ou la réécriture refuse :
un essai d'évasion se voit à part) avec `detail` `{ok, for: test|save, ms, compile_ms, scenarios, scenarios_passed,
hash}` ; `saved` (`detail` : module, version, statut, auteur, empreinte, classes, octets) ; `compiled` (une version
construite hors du cache, `DEBUG`) ; `broken` (`WARN`) ; `approved`, `rejected` (`by <opérateur>`) ; `stuck` (`ERROR`).
Le journal `Forge` a en plus : le démarrage (`the Forge is ready in 46 ms: ECJ 3.46.100, 7 of 7 built-in modules built,
2 forged versions`), la vérification des versions forgées, chaque refus de la garde avec ses violations brutes.

## Les outils du Forgeron (`ForgerTools.kt`)

Tous des `ForgeTool` (cachés sans le moteur et la Forge). Sans Forge : `DENIED (forge_off): the Forge is
unavailable: <raison>` pour `module_list`, `module_read`, `forge_test`, `forge_save` ; **coupe-circuit posé** :
`forge_test` et `forge_save` refusés `DENIED (forge_off): the Forge was switched off by <opérateur>: <raison>`, les
lectures continuent ; `game_ids` ne dépend pas de la Forge. Définitions (nom, description, schéma, telles que le SDK
les envoie) : **3 191 caractères** pour les cinq.

| Outil | Effet | Délai | Description (texte exact) |
|---|---|---|---|
| `module_list` | `READ` | 5 s | Lists the arsenal, one line per module: its latest version and status (ready, pending: an operator must approve it, rejected, broken: it no longer compiles), who saved it, its summary, parameters and scenarios, its last problem, and its other versions. Version 0 is built-in: read those for examples. |
| `module_read` | `READ` | 5 s | Reads the Java source of a module of the arsenal, its latest version when version is left out: to start from a module close to what you want, or to fix one. A fix is saved as the next version of the same name. |
| `game_ids` | `READ` | 5 s | Lists the ids a module may write, as the SDK takes them (without minecraft:), sorted, 150 at most: creature types (entity), items, blocks, the particles the particles act knows, sounds, effects, attributes (the players' and the creatures'), biomes, structures, dimensions, punishments, launch directions. Narrow with contains. |
| `forge_test` | `READ` | 45 s | Tests a module without saving it. Compiles the whole file against the SDK, checks it against the sandbox, then runs it at the bench, a simulated world: a smoke run of one simulated minute with sample parameters and facts, the acts it asked checked dry by the real tools, then each method of its Scenarios. Answers ok with what ran, or where it stopped and each problem with its line and hints: fix them and test again. Nothing touches the world. |
| `forge_save` | `ENGINE` | 45 s | Saves a module as the next version of its name in the arsenal, after the same tests as forge_test, which must all pass, with one scenario at least. The version is ready for the Director, or waits for an operator's approval when the server asks for one. A saved version never changes: a fix is the next version. |

## Écarts et décisions

1. **`Forge.noteFault` (question de M5-09)** : ajoutée **au contrat** `Forge`, méthode par défaut sans effet
   (`DisabledForge`, `FakeForge` inchangés) ; `ForgeService` la passe à `ArsenalStore.noteFault` (en mémoire, tout fil :
   la version reste `ready`, son `problem` devient la faute). Le moteur de M5-11 (fusionné) prend un paramètre
   `noteFault: (ModuleRun, Fault) -> Unit` : M5-21 le branche par
   `noteFault = { run, fault -> services.forge.noteFault(run.module, run.version, fault.text) }` (passer par
   `services.forge` marche aussi avec une Forge désactivée). `module_list` et `/narrator forge show` la montrent
   (`last fault: limit in timer: time budget at TagGame.java:41`) jusqu'au redémarrage.
2. **Garde, manifeste, réécriture sur `Dispatchers.Default`**, pas sur le fil du compilateur (§1.1) : l'API
   d'`EcjCompiler` ne prend que des compilations ; c'est hors du thread serveur, ce qu'exige le critère.
3. **Texte d'une version `broken`** : `FAILED: x v1 is broken: <cause>` (le §6.4 disait `… no longer compiles: <premier
   diagnostic>`) : la cause peut aussi être une source changée sur le disque ; celle d'une construction ratée commence
   par `it no longer builds against the SDK of now: `.
4. **`rejected`** : `Invalid arguments: … was rejected by an operator: deploy another version` (non tranché au design).
5. **`module_list`** : une ligne par module (la dernière version, quel que soit son statut), les autres en fin de
   ligne (`also v1 ready`) ; en-tête `arsenal: N modules (b built-in, f forged)` (un module compte comme « de départ »
   s'il a une version 0). **`module_read`** sans version : la dernière, quel que soit son statut (pour corriger une
   version `broken` ou `pending`).
6. **`forge_test` et `forge_save` refusés sous le coupe-circuit** (le Forgeron n'est plus câblé, mais une tâche peut
   encore finir son tour) ; `forge_save` refuse une note vide.
7. **Décision `refused`** (et non `tested`) quand la garde ou la réécriture refuse.
8. **Démarrage** : les versions forgées `ready` et `pending` sont **toutes** construites en tâche de fond (le §6.1 voulait
   `broken` « calculé au démarrage ») ; 64 noms × 20 versions au pire, à ≈ 15 ms chacune.
9. **`save` exige un scénario avant le banc** (refus immédiat, sans faire tourner la fumée).
10. **Le rapport** fait au plus 5 981 caractères (pour l'`Invalid arguments: ` devant).
11. **`Diagnostics.kt`** (M5-02) touché : les noms des paramètres ; KDoc et exemple mis à jour.

## Ce que les tâches suivantes doivent savoir

### M5-21 (l'assemblage)

- `createForge` : `ForgeService(services).also { it.start() }` ; `NoClassDefFoundError` (ECJ absent) au constructeur →
  `DisabledForge("ECJ is missing: …")`. `start` fait déjà `ModuleHost.preload()` hors du thread serveur.
- **Le moteur doit partager `forgeService.lostThreads`** (`ModuleThreads(lost = forgeService.lostThreads)` dans
  `MechanicsService`, passation M5-11) : le plafond des fils perdus est celui de toute la Forge ; un dépassement rend
  la Forge indisponible (`available` faux) et écrit `forge stuck` (déjà fait ici), et le moteur désactive ses modules à
  sa seconde suivante (M5-11). Le message aux opérateurs que demande M5-11 reste à M5-21 (le `LostThreads` est créé par
  `ForgeService`, sans autre rappel : lire `forge.unavailableReason`, ou ajouter un rappel au constructeur s'il le faut).
- **`noteFault`** : `noteFault = { run, fault -> services.forge.noteFault(run.module, run.version, fault.text) }` pour
  le paramètre du `ModuleEngine` (écart 1).
- Quand la Forge est désactivée (`DisabledForge`), il n'y a pas de `lostThreads` à partager : le moteur prend alors un
  `LostThreads()` à lui (aucun module ne se construit de toute façon).
- **L'`EngineActions` du moteur doit connaître `moduleOnlyTools()`** (`hud`, `place_blocks`, `creature_attack`) et
  tous les outils des actes des modules (ceux de `MechanicsService.engineTools`, plus ces trois) : les vérifications à
  sec du banc (`ForgeService.engineDryCheck`) prennent exactement cet ensemble (dédoublonné) ; un outil que le moteur
  n'aurait pas serait accepté au banc et refusé `unknown tool` en jeu.
- `ShutdownSequence` appelle déjà `forge.stop()` après les mécaniques.

### M5-11 (le moteur des modules, fusionné)

- Fautes : son paramètre `noteFault` se branche sur `services.forge.noteFault(run.module, run.version, fault.text)`
  (M5-21).
- `Forge.build(module, version)` : refus ci-dessus (`ForgeService.AWAITING_APPROVAL`, `FAILED: … is broken: …`,

  traduit en `MechanicRejected` avec le même texte. Au redémarrage, `ModuleRun.hash` peut être comparé à
  `built.entry.hash`. Un appel de `build` du serveur : quelques µs depuis le cache, ≈ 15 à 25 ms sinon (hors du thread
  serveur ; à appeler depuis une coroutine).

### M5-13 (le Forgeron : câblage et prompts)

- Les textes des outils et des réponses sont ci-dessus ; à dire dans `forger.md` : `forge_test` d'abord, lire la première

- Le coupe-circuit : les deux outils qui écrivent refusent `DENIED (forge_off)` ; une tâche annulée s'arrête de toute façon.

### M5-15 à M5-17 (l'arsenal de départ)

- `ArsenalScenariosTest` prend **tout seul** chaque `src/main/resources/narrator2/forge/arsenal/<nom>.java` de

- Les textes d'un échec sont ceux que lirait le Forgeron (rapport complet dans le message de l'assertion).
