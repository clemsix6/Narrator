# Passation M4-20 : les paris

Vague C de M4 (`design/M4.md` §22.2, §5.6, §18.2). Elle livre `/bet`, le règlement des paris à la fin d'un défi ou
d'un duel, et l'application des instructions de règlement, en s'appuyant sur le séquestre de M4-15 (`ItemLedger`) et
sur la fin commune de M4-12 (`BetBook`). **Règle du propriétaire tenue** : un pari se fait avec de vrais objets, mis en
séquestre ; rien ne va au Narrateur ; aucun objet ne se perd, sauf la mise perdue, qui va aux gagnants. Le serveur tourne
toujours avec `DisabledMechanics("not wired yet")` : M4-23 assemble. **En cas de contradiction avec `M4.md`, le code et
cette passation font foi.**

Aucun contrat sans propriétaire n'a changé (`Mechanics.kt`, `MechanicsTypes.kt`, `MechanicsState.kt`, `Challenges.kt`
intacts).

### API

```kotlin
class Bets(services, store: StateStore, ledger: ItemLedger = services.guards.items, clock: Clock = services.clock) : BetBook, MechanicPart {
    fun bet(player: ServerPlayer, ref: Ref, on: String): Component       // ChallengeControl.bet ; thread serveur
    override fun settle(state, challenge, ending, winners): Pair<MechanicsState, String?>   // pur
    // MechanicPart : everyTick, everySecond, onJoin appliquent les instructions des propriétaires en ligne
    companion object { NOBODY = "nobody"; BET = "bet"; SETTLED = "settled"; fun refused(text); fun challengeRef(typed): Ref? }

```

## Le cycle d'un pari, tel que le code l'applique

### `/bet <id> <player|nobody>`

- `id` : `C-50`, `c50` ou `50` (`Bets.challengeRef`) ; sinon `command.unknown_challenge` avec ce qui a été tapé.
  Moteur indisponible : `mechanics.unavailable` (vérifié par la commande, avant `ChallengeControl.bet`).
- Refus, dans cet ordre, **sans rien prendre** (gris italique, comme `/offer`) : défi ou duel absent de l'état
  (`command.unknown_challenge`) ; paris fermés (`bet.closed` : défi pas `RUNNING`, `betsCloseAt` nul ou passé ; donc
  aussi un duel en invitation et un défi en jugement) ; déjà parié sur ce défi (`bet.already`) ; choix inconnu
  (`bet.unknown_option`, `{options}` = les noms possibles puis `nobody`, tels qu'à taper) ; main vide ou joker
  (`bet.no_item`, `ItemLedger.hold` rend `null`).
- Choix : un participant **encore en lice** (ni `doneAt` ni `out`), par son nom sans tenir compte de la casse, ou
  `nobody`. Un participant tardif (`late`) peut être choisi. Un parieur peut être participant, et parier sur lui-même.
- Mise : `ledger.hold(player, MAIN_HAND, STAKE, Escrow.stakeDeadline(fin prévue), canon = id, "a bet that Mimosa
  wins")` — fin prévue = `endsAt`, plus `mechanics.judgeMinutes` pour un défi `judged`. Puis, **dans le même tick**,
  le `Bet` entre dans l'état du défi (`what` en forme courte : `12x iron_ingot`, sans `minecraft:`).
- Réponse : `bet.placed` (`{items}` = compte et nom de la pile, comme les lignes du registre ; `{on}` = le nom du
  participant ou `bet.on_nobody` ; `{id}` = `C-50`), avec le préfixe `[Narrateur → toi]`.
- Décisions : `ledger held` (registre ; ligne lue par le Chroniqueur : `12x minecraft:iron_ingot held as stake on C-50
  until 2026-10-26 20:20: a bet that Mimosa wins`) et `mechanic bet` (sujet `C-50`, `Josiane bets 12x iron_ingot on
  Mimosa (stake 812)`, conversation `mechanics:C-50`, `detail` : `bettor`, `on`, `stake`, `items`).

### Règlement (`settle`, pur, dans l'`update` de `Challenges.finish`)

- Paris gagnants : ceux sur un gagnant (`won`), ceux sur `nobody` (`lost`, donc aussi le nul d'un duel) ; aucun pour
  `expired` et `cancelled`.
- Aucun pari gagnant : chaque mise est rendue (`Settlement(owner, stake)`).
- Sinon : chaque parieur gagnant récupère sa mise, et les mises perdantes vont aux paris gagnants **à tour de rôle,
  dans l'ordre des paris** (`shares` : la première mise perdante au premier pari gagnant, la deuxième au deuxième…).
- Une instruction par pari, **pour tous les parieurs, en ligne ou non**, ajoutée à `MechanicsState.settlements` dans le
  même `update` que la fin du défi (jamais deux fois pour une même mise ; les autres instructions restent).
- Segment de la ligne `CHALLENGE`/`DUEL` (≤ `LINE_MAX` = 400, les derniers parieurs comptés `(+N more)`, noms échappés) :

```
bets: Josiane bet 12x iron_ingot on Mimosa, got it back with Bartok's 32x cobblestone; Bartok bet 32x cobblestone on nobody, lost it to Josiane
bets: Josiane bet 12x iron_ingot on Mimosa, got it back
bets: every stake given back (cancelled): Josiane 12x iron_ingot on Mimosa; Bartok 32x cobblestone on nobody
bets: every stake given back (expired): …            bets: every stake given back (no winning bet): …
```

### Application des instructions (la partie)

- `everyTick` et `everySecond` : chaque instruction dont le propriétaire est en ligne est appliquée. Placée **après**
  `Challenges` dans la liste des parties, une fin vue à la seconde (ou au fait) est réglée dans le même tick.
  Les instructions du démarrage et de la réconciliation (`Reconcile.drop`, `to = null`) passent par là aussi.
- `onJoin` : les instructions du joueur, **avant** le `JOIN` des garde-fous (phase `mechanics_before_guards`).
- Appliquer = `ledger.release(owner, stake, now)` (`to` nul) ou `ledger.forfeit(owner, stake, to, now)`. Le registre
  fait le reste : remise au gagnant dès que les deux sont en ligne (tout de suite, ou au contrôle de chaque seconde
  des garde-fous), sauvegardes, ce qui ne rentre pas, l'échéance de secours, et les messages `bet.won`, `bet.lost`,
  `bet.returned` (je n'en envoie aucun).
- L'instruction quitte l'état **après** le mouvement du registre : un crash entre les deux la rejoue, sans effet
  (`release`/`forfeit` rendent faux pour une mise déjà rendue, cédée ou partie). Une instruction qui lève est retirée,
  loguée en erreur : la mise revient à son propriétaire à son échéance de secours, jamais perdue.
- Décision `mechanic settled` par instruction : sujet = le propriétaire, `stake 812 (12x iron_ingot on C-50): given
  back | ceded to Josiane | nothing more to do (already settled or back)`, `detail` : `stake`, `to`, `canon`,
  `applied` ; `INFO`, ou `DEBUG` quand rien ne bouge.

## Écarts par rapport au design, et pourquoi

1. **Des instructions pour tous, pas seulement pour les absents** (§5.6 : « le règlement écrit […] des instructions »
   pour un joueur hors ligne). `settle` est pur (contrat de M4-12) : il ne peut pas toucher au registre. Un seul chemin
   pour tous, appliqué dans le tick même pour les joueurs en ligne ; c'est aussi celui des règlements produits par le
   démarrage et la réconciliation (M4-02).
2. **Un participant déjà arrivé ou éliminé n'est plus un choix** : parier sur une victoire acquise (`winners` 0 ou N,
   liste fermée) serait un vol des autres parieurs ; sur un éliminé, une perte sûre.
3. **Décisions** : `mechanic bet` et `mechanic settled` (noms du §19), en plus de celles du registre. `settled` est
   par instruction (pas par défi) : c'est elle qui montre qu'une instruction rejouée n'a rien fait.
4. **Le segment `bets:`** dit qui a misé quoi sur qui et où est partie chaque mise (le §4.4 n'en donnait qu'un exemple) :
   le Directeur peut se moquer du perdant sans rien deviner.
5. **`/bet 50`** est accepté (comme `C-50`) ; les suggestions de `<id>` sont les défis et duels `RUNNING` dont la
   spécification a `bets` (la vue `ChallengeView` n'a pas `betsCloseAt` : la fermeture est dite par la réponse).
6. `Bet.what` est en forme courte (`12x iron_ingot`), comme le dit le KDoc de `Bet`.
7. `Bets.refused` duplique le style des refus de `/offer` ; `placed` reprend la mise en forme de `ItemLedger.line`
   (qui ne sait remplir que `{items}`, et `bet.placed` a aussi `{on}` et `{id}`) : `ItemLedger.kt` n'est pas à moi.

## Ce que les tâches suivantes doivent savoir

### M4-23 (assemblage)

- `val bets = Bets(services, store)` (le registre par défaut est `services.guards.items`), passé à
  `Challenges(services, store, bars, stakes, bets = bets)` ; **dans les parties après `Challenges` et `Duels`** (un
  règlement dans le même tick que la fin) ; `MechanicsService.challenges.bet` délègue à `bets.bet`.
- `BetCommand` vérifie déjà `services.mechanics.available` ; `DisabledMechanics.bet` reste correct.
- Le GameTest `betIsACommandForEveryPlayer` attend `mechanics.unavailable` sans moteur, et
  `command.unknown_challenge` (`C-999999999`) une fois le vrai moteur branché : il passe dans les deux cas.

### M4-19 (duels, en parallèle)

- `/bet` n'ouvre que si l'entrée est `RUNNING` et `betsCloseAt` posé et pas encore passé : posez `betsCloseAt` au
  **départ** du duel (les deux acceptations), comme `Challenges.betWindow` (`min(betWindowMinutes, minutes / 3)`,
  une minute au moins). Un duel en invitation répond `bet.closed`.
- Un nul (`Ending.LOST`) paie les paris sur `nobody` ; `CANCELLED` (refus, invitation échue) rend tout. Rien d'autre à
  faire : `finish` appelle `settle`.

### M4-21 (commandes d'administration)

- `/narrator challenge cancel` rend toutes les mises (`(cancelled)` dans la ligne). `/narrator guards <player>` montre
  déjà les mises (`stake`) du registre. Les instructions en attente (`MechanicsState.settlements`, parieurs absents)
  pourraient s'afficher dans `/narrator challenge list` si l'on veut.

### M4-22 (prompts)

- `director.md` : quand un défi a `bets: true`, les joueurs parient avec `/bet C-50 <joueur|nobody>` (la pile tenue en
  main, pendant les premières minutes) ; le Narrateur ne prend jamais de mise, ni ne réclame un pari. La ligne
  `CHALLENGE`/`DUEL` finit par le segment `bets: …` ci-dessus : de quoi railler un perdant.
- `chronicler.md` : `ENGINE ledger held …: … held as stake on C-50 until …: a bet that Mimosa wins`.

### M4-24 (évals, recette)

- Un pari de bout en bout avec le vrai moteur : `/bet` par le répartiteur (deux joueurs), fin du défi, objets remis.

  sa propre horloge, un faux Directeur et la vraie mémoire :
  - pari gagné et deux paris perdus : réponses `bet.placed`/`bet.already`, mise en séquestre (échéance de secours),
    décisions `bet` ; fin à la seconde, réglée dans la même seconde ; le gagnant reçoit les deux mises perdantes, les
    registres vides, ligne exacte, messages `bet.returned`, `bet.won`, `bet.lost` ;
  - annulation par un opérateur, puis défi jugé non jugé (`expired`) : toutes les mises rendues, lignes exactes, mise
    d'un défi jugé avec le jugement dans son échéance, `bet.closed` pendant le jugement ;
  - deux parieurs absents au règlement : instructions en attente ; le perdant revient (mise cédée, en attente dans son
    registre), puis le gagnant (sa mise rendue à sa connexion, la mise perdue remise une fois les deux en ligne) ;
    instructions rejouées sans effet (`settled` : `applied` vrai, vrai, faux, faux) ;
  - redémarrage avec des mises en jeu : état passé par le codec du monde, joueurs relus de leur fichier, nouveau

    tick ;

    paris fermés ; rien n'est pris ;

  - `/bet` par le vrai répartiteur avec les droits d'un joueur.
