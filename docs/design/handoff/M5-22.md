## Défauts trouvés

1. **Bloc `fallback` de l'API (classifieur `cyber`)** : le client tombait (`Unknown ContentBlock`), l'appel n'était pas tracé, et la tâche finissait en `engine error`. **Corrigé par CLAUDE-FALLBACK** ; vérifié en F2, passe 4 (ci-dessus). Il reste à voir sur une conversation où une requête suit un repli (le risque d'un 400 que CLAUDE-FALLBACK signale).
2. **`Diagnostics` (M5-02)**, deux trous, **corrigés ici** (le fichier est hors liste, à la demande du superviseur) :
   - Une méthode inconnue d'un type du SDK, sans nom proche (`ctx.acts().actionbar(…)`), ne donnait **aucun** indice. Elle reçoit maintenant :
     - le nom que le SDK lui donne (une petite table de synonymes : actionbar → `hud`, sendMessage → `say`, find → `player`, runLater → `after`, setBlock → `place`…), ou le même nom sur un autre type ;
     - puis `methods of Acts (ctx.acts()): …` : la liste des méthodes du type avec leurs paramètres, sans type de retour, 800 caractères au plus, écrite une fois par rapport.
   - Vu en F1 (`relay_race`) : `ctx.acts().ground()` donnait `hint: Acts (ctx.acts()): Pending sound(String player, String sound)`, le nom le plus proche par distance d'édition. Le même nom sur un autre type passe maintenant devant : `ModuleContext (ctx): Ground ground()`.
   - `DiagnosticsTest` : 11 tests verts, dont un nouveau.
3. **`sdk.md` ne dit pas que `hud` n'entre pas dans les 30 actes par minute** (`ActQueue` ne le compte pas). En F4, le Forgeron a ralenti son module en croyant le contraire. Transmis : M5-FIX-2 précise `sdk.md`.
4. **`LeakWatch`, un WARN sur un module sain** : `the classes of C-1 orbiting_chickens are still in memory 120 s after its end: a leak`, pendant la soirée. C'est un module de départ, fini `fulfilled`. C'est probablement la piste de M5-10 : le cadre compilé du fil des modules garde la classe du dernier module jusqu'à l'appel suivant. Non examiné ici.
5. **Promesses par allusion** avant le `TASK` (M5-20 : « ne promets jamais aux joueurs un module qui n'existe pas encore »). Deux fois, une ligne de teaser dans le tour qui commande :
   - « le ciel prépare quelque chose de bondissant » (F3) ;
   - « Le Narrateur prépare une épreuve où le sable ne vous sauvera pas » (soirée).
   Rien de précis n'est promis, mais si le Forgeron avait échoué, ce serait une promesse non tenue. À trancher dans `director.md` (304 caractères de marge).
6. Sans gravité :
   - le brief de F3 est en anglais (le Forgeron lit les deux) ;
   - des tics à surveiller : « Mesdames et messieurs » (trois fois), « céleste » (« Haute Administration Céleste », « direction céleste ») ;
   - « Interruption des programmes ! » deux fois : ce sont les arrêts du banc lui-même (`cleanUp`), que le Directeur commente.

Rien de nuisible n'a été sauvé. Aucun module n'a vu une donnée privée ni la clé (vérifié dans ce que lisent les joueurs). **Aucune faute à tort** (problème de M5-LOAD) sur les modules sains : les 7 modules joués 40 s et les modules de la soirée ont 0 faute.

### Le GameTest de bout en bout (`ForgeEndToEndTests`)

Le vrai Directeur et le vrai Forgeron du serveur de test parlent à un `FakeAnthropic` qui joue les deux ; la vraie Forge et le vrai moteur font le reste :
1. **La commande** : une prière déclenche `forge_module`. Le chapitre s'ouvre avec 47 outils et la ligne `Arsenal`.
2. **Le Forgeron** a ses deux blocs système (`forger.md`, `sdk.md`) et ses cinq outils. Il fait :
   - `module_list` ;
   - un `forge_test` qui ne compile pas (`[1] error PasswordRace.java:35:20: The method actionbar(null, String) is undefined for the type Acts`) ;
   - un `forge_test` ok (3 scénarios sur 3) ;
   - `forge_save` : `password_race v1 ready`, par `forger T-…`, avec ses décisions `forge`.
3. **Le déploiement** : le `TASK` réveille le Directeur, qui lance un défi jugé puis déploie le module en loi, en arbitre de ce défi, et l'annonce.
4. **La situation** montre `Modules:`, et la barre d'action montre le mot de passe à l'envers.
5. **Le jeu** : un mauvais mot, puis le bon. Le défi est gagné et ses 3 biscuits payés ; le Directeur reçoit le `CHALLENGE` et félicite, puis le module finit seul (`fulfilled`, loi `retired`, `MODULE … ended by itself`).
6. **La fin** : le chapitre se ferme avec son résumé.

Le serveur tourne à environ 20 ticks par seconde (chaque tick dort). Le test vert seul prend 32 s.

Un **lot à lui**, et non le lot `director` que citait la fiche : deux tests qui changent la configuration côte à côte parlent au faux LLMGW l'un de l'autre. Un échec de mon test qui laissait le chapitre ouvert a aussi fait échouer `DirectorEndToEndTests` au lot suivant (un Directeur endormi garde son chapitre). Le test ferme donc le chapitre dans son `finally`.

1. **F1, F2 et F4 passent par `Workers`, pas par le Directeur** : on mesure le Forgeron seul, sur une commande écrite comme celle du Directeur ; le Directeur dort, donc pas de tour payé pour lire le `TASK`. **F3 et la soirée** passent par le vrai Directeur, et le Directeur a commandé lui-même trois modules (`concours_de_sauts`, `mental_math`, `metronome` v2).

Il est arrêté comme à l'arrêt du serveur, puis son état est réencodé et repris par un moteur neuf. Le moteur du serveur ne peut pas s'arrêter dans un GameTest.
