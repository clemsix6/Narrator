### Le schéma (V4)

```
ideas(id P-, created_at, kind, title, pitch, fit, players UUID[], register, novelty, fun, fairness, refs BIGINT[],
      module, brief, status open|dropped|expired, dealt, last_dealt_at, expires_play_s, closed_at, close_reason,
      source, run_id, conversation_id)
line_labels(event_id, ts, source, register, dark, cruel, flat, out_of_character, repeats, crutches VARCHAR[], reason, latency_ms)
```

- Les notes de `line_labels` sont `NOT NULL` : une réplique est étiquetée entière ou pas du tout.
- Vues : `narrator_lines(id, ts, recipients, text, register, dark, cruel, flat, out_of_character, repeats, crutches)`
  (les répliques du canal `narrator`, les dernières étiquettes de chacune, nulles sans relecture) et
  `mem_ideas(ref, kind, status, title, pitch, fit, players[], register, dealt, created_at)`.
- `ideas` est une table de la mémoire (`MemorySchema.TABLES`), `line_labels` une trace ; aucune des deux n'est décrite
  au modèle, qui les lit par leurs vues. Les ids des idées viennent de `IdKind.MEMORY`.
- `SchemaDoc` : 7 067 caractères, environ 2 356 tokens (en-tête 562/600, vues 2 167/2 300, macros 781/900, tables
  1 797/1 800, mémoire 1 290/1 300, exemples 465/500). **Il ne reste presque plus de place** dans les tables et la
  mémoire : une vue de plus devra en raccourcir une autre.

### Les idées dans la mémoire

- `Idea : MemoryRow` (`ref` `P-…`, `funScore` pour `fun`). `RefKind.IDEA` est **hors de `searchable`** (`recall` ne
  rend jamais d'idée), **dans `indexed`** (l'index BM25 commun, pour la règle « pas de redite »), **hors de `facts`**
  (jamais preuve d'un trait, d'une compétence, d'un document, ni ref d'une note), **hors des archivables** (une idée se
  clôt).
- `MemoryStore` :
  - `addIdea(draft, author): Added<Idea>` — **version simple** : `VoiceGuard` sur titre, pitch et `fit` (la règle
    générale du magasin), notes 1..5, heures 1..168, 8 joueurs et 6 refs au plus, brief ≤ 1 500 ; écrit `open`, échéance
    `jeu du monde + heures`, indexée (`ideaText` = titre et pitch), auditée, décision `memory written`.
  - `dropIdea(ref, reason, author): Idea` — `dropped`, `closed_at`, `close_reason` (≤ 160), audité.
  - **`dealt(refs, channel, context: RecallContext)`** — `dealt + 1`, `last_dealt_at`, une ligne `recalls` chacune ;
    une ref d'une autre sorte est une erreur de l'appelant (`IllegalArgumentException`), une idée absente est ignorée.
  - `ideas(status = OPEN, limit = 50)` — les plus récentes d'abord ; `null` : toutes.
- `Memory.openIdeas()` : `DisabledMemory` et **`MemoryService` rendent une liste vide** (pas encore de cache).
- `RunContext.role: Role?` (nul par défaut) est posé par `MemoryAgents.run` : `contexts[id] = context.copy(role = role)`.
  `author()` : `STORYTELLER` pour le Scénariste, sinon `DREAMER` pour un rêve, `CHRONICLER` sinon. Les appelants n'ont
  rien à changer.
- `MemoryAgents.run` accepte `CHRONICLER`, `DREAMER`, `STORYTELLER` (buts `chronicle`, `dream`, **`programme`**) et lève
  `IllegalArgumentException("<role> is not a memory role")` sinon ; la conversation du Scénariste a
  `storytellerAvailable = true` (elle voit `inspire`).

### Le Directeur

- `DirectorSignal.StyleNote(kind: StyleNoteKind, text, at)`, `StyleNoteKind { DARK, CRUEL, OUT_OF_CHARACTER, FLAT,
  REPEATS }` **dans l'ordre de gravité**. `text` est ce qui suit `tone check: `.
- Urgence `NEXT` : jamais de réveil, valeur 0 pour un battement (comme une note de la mémoire). Au prochain envoi (réveil,
  ou entre deux appels d'outils), elle devient `Engine: tone check: <text>` (échappé, coupé à 400) ; **une seule par
  requête, la plus grave**, les autres sont laissées. Un silence (pause, blocage) les jette.
- `SituationReport` : la ligne `services.style.situationLine(now)` en dernier, échappée, coupée à 400, seulement quand
  elle n'est pas vide ; une exception donne `Style: unavailable (…)` et un `ERROR`.

### La configuration

```json
"style":     { "lineReview": true, "toneNotes": true, "refuseRestingOpeners": true },
"dashboard": { "enabled": true, "port": 8770 },
"prices":    { "claude-opus-5-5": { "input": 4.0, "output": 20.0, "cacheRead": 0.2, "cacheWrite": 8.0 },
               "claude-haiku-5-5": { "input": 0.1, "output": 0.5, "cacheRead": 0.01, "cacheWrite": 0.2 } },
"memory":    { …, "programme": true }
```

- `dashboard.port` : 0 ou 1 024 à 65 535. Prix : nombres finis, positifs ou nuls ; un id de modèle non vide.
- **`prices` est une table libre** (`ConfigStore.FREE_FORM`) : un modèle par défaut se fusionne clé par clé avec son
  défaut (`"claude-opus-5-5": { "output": 25 }` garde les trois autres) ; un modèle nouveau donne ses quatre prix, sinon
  le fichier est refusé.

## Écarts et décisions

1. **`StyleWatch.atRest()`** en plus du §12.1 : le refus de `say` doit citer **toutes** les amorces au repos (§3.5), et
   `inspire` écarte les béquilles au repos (§5.2). `Style.kt` ne bouge plus avant M6-16 : le contrat devait les porter.
2. **`LineLabels.text`** : la note de ton cite la réplique ; la veille peut l'avoir perdue (file pleine). **`record()`**
   évite à M6-02 de recopier la conversion.
3. **Notes `NOT NULL`** dans `line_labels` (et `LineLabelsRecord` sans nul) : la relecture n'écrit rien quand elle
   échoue.
4. **`line_labels` hors de la description** du modèle, et `mem_ideas` sans les notes : le budget de `SchemaDoc` ne les
   tenait pas (tables 1 891/1 800, mémoire 1 299/1 200). Cent caractères passent de l'en-tête (562 utilisés) à la mémoire.
5. **Une idée est une `MemoryRow`** : lire une ligne, l'audit, l'annulation d'un travail, l'index et `/narrator memory
   show` la connaissent sans cas particulier. `RefKind.indexed` remplace `searchable` dans `MemoryLog.revert` (sinon,
   annuler un rêve aurait laissé l'index de ses idées) ; `RefKind.facts` remplace `RefKind.entries` pour les preuves et
   les refs de note (une idée n'est pas un fait).
6. **`dealt(…, context)`** au lieu de `at` : le magasin date ses écritures (règle du magasin), et la ligne `recalls` a
   besoin de la conversation et du tour.
7. **Effet `ENGINE`** pour `propose_idea` et `drop_idea` : c'est celui des écritures de la mémoire (`remember`,
   `resolve`, que le Scénariste a aussi). La règle testée : aucun outil `SPEECH`, `WORLD`, `TASK` ; les outils `ENGINE`
   sont les quatre écritures de la mémoire.
8. **`inspire` demande aussi le Journal** (§5.2 : « proposé quand le Journal est disponible »).
9. **Une note de ton par requête**, la plus grave, rendue par le Directeur : `ToneWatch` (M6-03) ne voit pas les
   réveils ; c'est donc le rendu qui tient « une note par réveil au plus » du §4.3. La cadence « une même dérive au plus
   toutes les 30 min » reste à `ToneWatch`.
10. **`addIdea` simple** : seules les bornes et la `VoiceGuard` (règle générale du magasin) ; rien des règles du §6.2.
11. **`MemoryService.openIdeas()` vide** : pas de cache sans son rafraîchissement, qui est à M6-06.
12. **`DisabledStyle.leastUsedRegisters`** rend une liste vide (sans Journal, `inspire` n'est de toute façon pas montré).
    `FakeStyle.leastUsed` vaut `ComicRegister.VOICE` par défaut.
