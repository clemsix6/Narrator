## Le serveur (§8.2)

- `DashboardServer.start(services, port)` : `HttpServer` sur `127.0.0.1` (adresse écrite en octets : jamais une autre
  interface, jamais IPv6), port `dashboard.port` (0 : un port libre). Deux fils démons `narrator2-web-N`. Le fil
  `HTTP-Dispatcher` du JDK hérite du drapeau démon du fil qui démarre le serveur : on le démarre depuis un fil démon
  éphémère (`narrator2-web-start`, une milliseconde), pour qu'un arrêt oublié ne retienne jamais la JVM (testé).
- `createDashboard` : `dashboard.enabled` faux → `DisabledDashboard("dashboard.enabled is false")` ; port pris →
  `WARN no dashboard: port 8770 of 127.0.0.1 is taken (…)` ; `NoClassDefFoundError` (pas de `jdk.httpserver`) →
  `the Java runtime has no jdk.httpserver module` ; toute autre erreur → `cannot listen on …`. Jamais d'exception : la
  ligne `ready` dit `dashboard off (<raison>)` ou `dashboard on http://127.0.0.1:<port>/`. **Le repli Netty n'est pas
  écrit** (§18.1, point 6 : à faire seulement si le serveur du propriétaire n'a pas le module).
- `stop()` : `server.stop(0)` puis `shutdownNow()` des fils, idempotent, quelques millisecondes (testé < 2 s).
- Une page tourne sur un fil du tableau de bord ; elle lit le Journal par `runBlocking` sur ce fil, jamais sur le thread
  serveur, et les états vivants dans les instantanés.

## La sécurité (§8.3)

L'ordre de `Routes.respond(call)` :

1. **Hôte** : `127.0.0.1:<port>`, `localhost:<port>` ou `[::1]:<port>` (casse ignorée), sinon **421** (rebinding DNS).
   Un tunnel SSH doit garder le même port local (`ssh -L 8770:localhost:8770`).
2. **Méthode** : `GET` et `HEAD` seulement, sinon **405** avec `Allow: GET, HEAD`. `HEAD` rend les en-têtes sans corps.
3. `/style.css` est servie **sans jeton** (aucune donnée, et la page de refus en a besoin) ; `/login?key=<jeton>` pose le
   cookie `narrator2=<jeton>; HttpOnly; SameSite=Strict; Path=/` et répond **303** vers `/` ; une clé fausse ou absente
   donne **403** sans cookie.
4. Toute autre adresse demande le cookie, sinon **403** (une page sans données ni barre de navigation).
5. La page de la racine du chemin (`Routes.PAGES`), sinon **404** ; une adresse mal encodée **400**.

- **Jeton** (`DashboardToken`) : 32 octets de `SecureRandom` en hexadécimal (64 caractères), tiré au démarrage et par
  `/narrator dashboard reset`, en mémoire seulement. **Comparaison en temps constant** : les deux côtés sont hachés en
  SHA-256 et les deux empreintes (toujours 32 octets) comparées par `MessageDigest.isEqual` ; le temps ne dépend ni de
  l'endroit où ils diffèrent ni de la longueur du candidat.
- **En-têtes sur toute réponse** (refus, feuille de style et 303 compris) : `Content-Security-Policy: default-src
  'none'; style-src 'self'; img-src 'self' data:; form-action 'self'; frame-ancestors 'none'; base-uri 'none'`,
  `X-Content-Type-Options: nosniff`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`. Le serveur du JDK
  normalise la casse des noms (`Content-security-policy`) : sans effet pour un navigateur.
- **Journal du mod** : les refus en `WARN` (tag `Web`), **une ligne par minute au plus**, avec le nombre de refus tus
  (`refused GET /turns (403): not signed in`, `… (2 more refused since the last line)`) : la méthode, le premier segment
  du chemin et la raison, **jamais la requête, le cookie ni le jeton**. Une page servie : une ligne `DEBUG` (sa racine,
  son statut, sa durée). **Écart** : une connexion réussie est une ligne `INFO` (`a browser signed in to the dashboard`,
  sans le jeton) : c'est un événement de sécurité, que le propriétaire doit pouvoir retrouver.
- **`/narrator dashboard`** (`command/DashboardCommands.kt`) : à un joueur, un `[Sign in]` cliquable
  (`ClickEvent.OpenUrl`) dont le texte ne montre pas le jeton (le journal du client garde le texte du chat, pas ses
  clics) ; à la console, le lien écrit en entier et le conseil de `reset` une fois connecté (Minecraft écrit les
  réponses de la console dans `logs/latest.log`). `reset` tire un nouveau jeton : les cookies et les liens donnés avant
  tombent ; décision `operator dashboard_reset` (sujet : l'opérateur).
- Accepté (§8.3) : le cookie n'est pas isolé par port ; deux tableaux de bord sur la même machine (deux worktrees) se
  disputent le même nom de cookie `narrator2` : on se reconnecte.

## Le rendu (§8.6) et l'API pour M6-11 et M6-12

**Vous ne touchez qu'à vos fichiers de `web/pages/`** (et à vos propres fichiers nouveaux) : chaque page est déjà
listée dans `Routes.PAGES` et branchée dans la barre de navigation. `Routes.kt`, `Html.kt` et `Svg.kt` sont à M6-10 ;
un manque se signale dans votre passation (ou se contourne dans votre fichier).

### Une page

```kotlin
object TurnsPage : WebPage {
    override val root = "turns"          // sert /turns et /turns/…
    override val label = "Turns"         // la barre de navigation
    override fun render(request: WebRequest, context: PageContext): Page? {
        val id = request.path.firstOrNull()                // /turns/42 → "42" ; request.path vide pour /turns
        val paging = Paging.of(request)                    // ?page=, 50 lignes
        val (rows, more) = paging.rows(context.read { c -> c.rows(SQL, paging.limit, paging.offset) { getLong(1) } })
        return Page("Turns") {
            filters(link("turns"), request, listOf(Filter.Choice("trigger", "Trigger", listOf("chat", "heartbeat"))))
            table(listOf("#Turn", "Started")) { rows.forEach { row { number(it); cell(context.time(…)) } } }
            pager(request, paging, more)
        }
    }
}
```

- **`render` rend `null`** pour « pas de telle page » (404). **`throw BadRequest("…")`** pour un paramètre faux (400).
  Une `JournalUnavailableException` ou une `JournalTimeoutException` qui sort de `render` devient une **503** qui le dit :
  inutile de les attraper, sauf pour montrer le reste de la page (comme la vue d'ensemble).
- **`WebRequest`** : `segments`, `root`, `path` (après la racine, décodés), `query` (première valeur de chaque
  paramètre), `param(name)` (null si vide), `int(name, défaut)`, `long(name)`, `with("page" to 2, "kind" to null)` (le
  lien de la même page, paramètres changés).
- **`Page(title, status = 200, refresh = null) { … }`** : `title` est le `<h1>` et le titre de la fenêtre.
- **`PageContext`** : `services`, `now`, `zone` (celle de `journal.timeZone`, sinon celle du serveur), `prices`,
  `time(instant)` (`21:30:12` aujourd'hui, `10-01 23:05` sinon), `ago(instant)`, et **`read { connection -> … }`** :
  une lecture du Journal à la fois pour tout le tableau de bord (sémaphore), 5 s d'attente au plus pour son tour puis
  5 s pour la lecture. Faites **une seule** `read` par page, avec toutes vos requêtes dedans.
- **`Connection.rows(sql, params…) { getLong(1) }`** : paramètres `Long`, `Int`, `String` ; délai de 5 s par requête.
  `TraceQueries(connection)` reste utilisable tel quel. **Aucune requête ne nomme `private_messages`** (M6-12 le teste).
- **`Html`** : `text(x)` (échappé), `h2`, `h3`, `p("texte", "classe")` ou `p("classe") { … }`, `div`, `section`,
  `span`, `strong`, `em`, `small`, `code`, `pre`, `br`, `a(link, "texte", "classe")`, `details("résumé") { … }`,
  `ul { li("…") }`, `dl { item("Terme", "valeur") }`, `table(listOf("Nom", "#Nombre")) { row("failure") { cell(x);
  number(n); cell("num") { … } } }` (un en-tête commençant par `#` est une colonne de nombres, alignée à droite).
  `element(nom, "attr" to valeur) { … }` (interne au module) n'accepte que des éléments connus, refuse tout attribut
  `on…` et `style`, et un `href`, `action` ou `src` qui ne commence pas par `/` (ou `#`) : **pas de lien externe, pas
  de `javascript:`, pas de style en ligne, par construction**.
- **Liens** : `link("players", name)` encode chaque segment (`/players/B%C3%A9a`), `link("decisions", query =
  mapOf("kind" to "guard"))` le reste ; un segment n'est jamais lu comme un chemin.
- **Pagination et filtres** (§8.5) : `Paging.of(request)` (`page`, `offset`, `limit` = une ligne de plus que la page,
  `rows(fetched)` → lignes et « page suivante ? »), `pager(request, paging, hasNext)`, `filters(lien, request,
  listOf(Filter.Choice(nom, libellé, options), Filter.Field(nom, libellé)))` (formulaire `GET`, valeurs reprises).
- **SVG** (`Svg.kt`) : `bars("titre", listOf(Bar("director", 1.92, "$1.92 · 340 calls")))` et `curve("titre",
  valeurs, "18:00", "20:00", "max")`. Couleurs par classes (`bar`, `line`, `axis`), jamais de `style=`.
- **Classes CSS** : `cards`/`card` (grille de cartes), `muted`, `failure`, `warning`, `num`, `lines`, `pager`,
  `filters`, `chart` ; sur une ligne de tableau : `failure`, `warning`, `muted`.
- **Liens que la vue d'ensemble émet déjà** : `/turns/<id>`, `/tasks/<id>` (M6-11), `/players/<nom>` (M6-12).
- **`/conversations/<id>`** : `ConversationsPage` appelle `TranscriptPage.render(id, request, context)` ; M6-11 possède
  les deux et peut changer cette délégation.
- **`notBuiltYet(title)`** (dans `Routes.kt`) sert aux pages vides ; une fois toutes les pages écrites, M6-17 le retire.
- **`NoScriptTest`** rend déjà la racine de chaque page de `Routes.PAGES` et ces chemins : `/turns/42`,
  `/turns?trigger=chat&page=2`, `/conversations/director-aaaa`, `/tasks/7`, `/decisions?kind=guard`, `/costs`,
  `/memory/M-1`, `/players/<nom piégé>`, `/players/Bartok`, `/mechanics`, `/forge/parade/1`, `/style`, `/sql?q=SELECT 1`,
  sur le Journal de `TraceDataset` (et sans Journal) : **vos pages doivent y répondre 200 ou 404** (jamais 500), sans
  `<script`, ni attribut `on…`/`style`, ni lien externe. `assertSafePage(what, response)` et `bodyText(response)`
  (fonctions de test internes, dans `NoScriptTest.kt`) font ces vérifications pour vos propres tests ; une réponse se
  rend sans socket par `Routes(services, DashboardToken(), port).respond(WebCall("GET", "/turns", null,
  "127.0.0.1:$port", listOf("narrator2=${token.value}")))`.

## La vue d'ensemble (`/`)

Cartes tirées des instantanés (aucune lecture du Journal) : Narrateur (phase, réglages, clé, réflexes), Directeur
(état, tour en cours, chapitre et contexte, tours de l'heure, boîte, rappels), Journal (santé), joueurs en ligne (lien,
mode, vie, faim, lieu, actif ou inactif), tâches ouvertes, mémoire (`MemoryCommands.statusLine` et ses lignes de
situation), mécaniques (`MechanicsCommands.statusLine` et `situationLines`), Forge (`ForgeCommands.statusLine`, état du
compilateur). Puis, d'**une** lecture du Journal : le coût des 24 dernières heures **par rôle** (barres SVG, prix par
modèle, total, appels d'un modèle sans prix comptés à part, la mention « ordre de grandeur derrière un abonnement ») et
les **15 derniers tours** (`TraceQueries.lastTurns`). Sans Journal, les cartes restent et la suite dit pourquoi.
`?refresh=15` recharge la page (`<meta http-equiv="refresh">`, de 5 à 3 600 s) ; un lien l'active et l'arrête.
La requête des coûts est `OverviewPage.COST_BY_ROLE` (interne au module, pour le test de M6-12).

## La configuration des GameTests

`dashboard.enabled = false` passe par **`build.gradle.kts`** : `cleanGameTestRun` et `cleanLiveGameTestRun` écrivent,
après avoir vidé le dossier, `config/narrator2/narrator2.json` = `{ "dashboard": { "enabled": false } }`. Le serveur de
test le lit au démarrage (le reste prend ses défauts). Un GameTest qui veut un tableau de bord en démarre un lui-même
par `createDashboard` avec un `NarratorServices` dont les réglages ont `dashboard = (true, 0)` (voir
`DashboardServerGameTests`). `/narrator reload` ne touche jamais le tableau de bord.

## Écarts et décisions

1. **`Dashboard` gagne `loginUrl()` et `resetToken()`** (pour `/narrator dashboard` et son `reset`) ; `url`,
   `unavailableReason`, `stop()` et la fabrique sont inchangés.
2. **La porte est dans `Routes.kt`** (`Routes.respond`, pure : un appel → une réponse), le serveur HTTP dans
   `Dashboard.kt` : les tests rendent chaque page sans socket (`NoScriptTest`) et vérifient le réseau à part
   (`DashboardServerTest`).
3. **`/style.css` sans jeton** (aucune donnée).
4. **`PricesTest` est fait ici** (le §15.1 le mettait à M6-11, la fiche de M6-10 me le donne).
5. **`build.gradle.kts`** porte la configuration des GameTests (aucun autre endroit ne précède le démarrage du serveur
   de test) ; **`DuckDatabaseTest`** : une assertion (2 → 3 connexions de lecture).
6. **Une connexion réussie se journalise en `INFO`**, sans le jeton (le §14 ne prévoyait que des `DEBUG`).
7. **La vue d'ensemble réutilise** les lignes d'état de `/narrator status` (`MemoryCommands`, `MechanicsCommands`,
   `ForgeCommands`) et `TraceText` : le même texte en jeu et dans le navigateur.
8. **Pas de repli Netty** : sans `jdk.httpserver`, le tableau de bord est éteint avec sa raison.
9. **La comparaison du jeton** hache les deux côtés avant `MessageDigest.isEqual` : sans cela, `isEqual` dépend de la
   longueur du premier argument.
