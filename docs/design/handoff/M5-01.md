# Passation M5-01 : contrats de M5 (la Forge)

Étape 0 de M5 (`design/M5.md` §17.2, fiche M5-01). Elle pose ce que les vingt tâches suivantes implémentent en
parallèle : le **SDK Java** des modules (`forge/api`, écrit en entier, Javadoc anglaise), les signatures de
`forge/rt` (corps provisoires), les **contrats Kotlin** (Forge, arsenal, modules déployés, état, budgets,
configuration `forge`), les familles d'outils et les commandes vides, l'**intégration d'ECJ** par Loom, les faux et
les échantillons. Le serveur tourne avec `DisabledForge("not wired yet")` et `DisabledModules` jusqu'à M5-21 ; le
Directeur garde ses **44 outils**. **En cas de contradiction avec `M5.md`, le code et cette passation font foi** (les
blocs de code des §4.2, §7 et §11 de `M5.md` sont le premier jet ; l'encart « Passation M5-01 » en tête de `M5.md`
résume les écarts).

`Sdk.VERSION = 1` est **figé** : il l'a été après la compilation du module témoin (relecture, constat 5), voir
« Le module témoin ». Une tâche qui trouve un défaut dans une signature du SDK ne la change pas : elle le dit dans sa
passation, avec le changement proposé ; un ajout (méthode d'une interface que les modules n'implémentent pas, type
nouveau) reste compatible.

## Le SDK

### Conventions (Javadoc de `Sdk`)

- **Identifiants** comme les outils du Narrateur les écrivent : **sans `minecraft:`** (`cow`, `diamond_ore`,
  `overworld`, `the_nether`, `story/mine_stone`), ceux d'un autre mod avec leur espace de noms. Le SDK accepte aussi la
  forme avec `minecraft:`, et `nether`/`end` pour une dimension. Le design disait « identifiant » sans trancher ;
  `ToolText` (« un identifiant sans `minecraft:`, comme les vues du Journal ») fait foi pour tout ce que lit un modèle.
- `Place` et `Cell` **normalisent leur dimension** dans leur constructeur compact, par `ToolText.dimension(
  ToolText.dimensionId(…))` (une seule source) : `Place("minecraft:overworld", …).equals(Place("Overworld", …))`. Une
  dimension absente ou une coordonnée non finie lève `ForgeRefusal`.
- Joueurs par nom, créatures par UUID texte ; temps en millisecondes epoch, délais en ticks ; listes rendues non
  modifiables, listes reçues copiées.
- Erreurs : `ForgeRefusal` (une `RuntimeException`) pour un appel du SDK refusé ; un acte n'est **jamais** refusé par
  une exception, son `Outcome` le dit ; `ForgeLimit` (une `Error`) pour une limite du bac à sable.
- **Pour les implémenteurs** : tout objet reçu d'un module est opaque (constat 8). Attention, un module **peut
  implémenter** `List`, `Map`, `CharSequence`, `Comparable`, `Iterable`, `Runnable` et les interfaces de
  `java.util.function` (la liste blanche les permet) : une `List<Cell>` passée à `Ground.place`, une `List<String>`
  passée à `Game.win` sont copiées **dans** l'appel armé, jamais lues après.

### Les écarts par rapport au §4.2

1. **`Limits`** (nouveau) : les limites qu'un module voit, en constantes publiques (abonnements, minuteurs, actes,
   créatures, journal, notes, `Storage`, `Ground`, `World.creatures`, réclamation, tailles, 20 ms, profondeur). C'est la
   **source unique** : `ForgeLimits` (Kotlin) les reprend par référence (`const val SUBSCRIPTIONS =
   Limits.MAX_SUBSCRIPTIONS`), la Javadoc les cite par `{@link}`, et un module peut s'en servir (`Limits.TICKS_PER_SECOND`).
   ECJ les inline (constantes de compilation) : aucun accès de membre dans le bytecode.
2. **`Who(type, uuid, name)`** (nouveau, avec `isPlayer()`) remplace `CreatureInfo` et les chaînes « type de créature
   ou nom de joueur » dans les faits : `CreatureHit(player, at, Who creature, damage, health)`, `PlayerHurt(player,
   at, cause, Who attacker, damage)`, `CreatureKilled(player, at, Who creature)`, `ProjectileHit(player, at,
   projectile, Who shooter, Who target)`, `PlayerDied(player, at, cause, Who killer)`, `CreatureAppeared(player, at,
   Who creature)`, `CreatureGone(player, at, Who creature, why)`. Pourquoi : (a) `CreatureInfo.own` dépend du
   **déploiement** qui reçoit le fait, alors qu'un fait est traduit une fois ; (b) le bus ne porte qu'un `EntityRef`
   (type, uuid, nom) : un `CreatureInfo` aurait demandé une recherche dans le monde au moment du fait, ou des valeurs
   inventées (vie maximale) ; (c) « zombie » est aussi un nom de joueur possible : `Who.type == "player"` lève
   l'ambiguïté. Un module sait si une créature est à lui par `ctx.creatures().get(uuid) != null`. `CreatureHit` gagne
   `health` (la vie après le coup, que le bus donne).
3. **`Events.on` rend une `Subscription`** (`cancel()`, `active()`), au lieu de `void` : un jeu à phases qui
   s'abonne et se désabonne aurait épuisé ses 16 abonnements ; ajouter un type de retour plus tard aurait cassé la
   compatibilité binaire. `F` doit être un des 20 records (jamais `GameFact` lui-même : `ForgeRefusal`).
4. **`Game.win`/`lose` rendent un `Pending`** (une fin d'arbitrage peut être refusée : défi déjà fini, gagnant hors
   des participants) et **`Game.running()`** existe (le Directeur peut finir le défi pendant que le module tourne).
5. **`Acts.title`, `sound`, `hud` acceptent `null`** : tout le monde en ligne (le compte à rebours d'un jeu). `hud`
   compte une ligne par joueur et par seconde ; `title` compte avec `say` (4 par minute).
6. **`Spawn`** a des copies `withDistance`, `withName`, `withTarget`, `withLifetimeMinutes`, `withHeight`,
   `withBaby` : `new Spawn(6, 8, null, false, 5, 0, false)` à sept arguments positionnels invitait aux inversions.
7. **`Pending.then`** : un seul rappel par acte (un second lève `ForgeRefusal`) ; donné après l'arrivée de
   l'`Outcome`, il est appelé au tick suivant ; jamais appelé après la fin du déploiement.
8. **`Outcome`** : statuts `ok`, `invalid`, `denied`, `failed`, `unknown`, `dropped` ; `creatures` jamais nul (le
   constructeur compact remplace `null` par une liste vide et copie).
9. **`ParamType`** donne les **formats** (JSON de `deploy_module params`, texte de `@Param.fallback` et de
   `Bench.start("nom=valeur")`) : `PLAYERS` = tableau JSON ou `Bartok,Mimosa` ; `PLACE` = objet
   `{"x","y","z","dimension"?}`, ou le **nom d'un joueur en ligne** (là où il se tient au déploiement), ou le texte
   `120 64 -30 [dimension]`. Toute valeur peut aussi venir sous sa forme texte, en chaîne JSON.
10. **`@Param`** : `fallback = ""` veut dire « aucune » (`Args` rend `null` pour un joueur, un texte, un lieu, une
    liste vide pour des joueurs) ; `INTEGER`, `NUMBER`, `BOOLEAN` non requis **exigent** un `fallback` ; un paramètre
    requis n'en a pas ; `min`/`max` bornent aussi la **longueur d'un `TEXT`** (300 caractères au plus de toute façon)
    et le **nombre de `PLAYERS`** (8 au plus).
11. **`Storage.put(clé, null)`** retire la clé ; `keys()` dans l'ordre de première écriture ; la limite de 8 Kio est
    comptée en **caractères** (`Limits.MAX_STORAGE_CHARS` = 8 192).
12. **`World.player`** rend `null` aussi pour un spectateur (comme `players()`, qui les exclut) ;
    `World.creatures` lève `ForgeRefusal` au-delà de 48 blocs ; `World.surface` est défini (premier bloc libre au-dessus
    de la hauteur `MOTION_BLOCKING`) ; `PlayerInfo.underground` est la notion du Narrateur (`PlayerStates` : pas de
    lumière du ciel et bien sous le niveau de la mer) ; `heldItem` vaut `air` main vide.
13. **`Cell.center()`** est le vrai centre (`x + 0.5`, `y + 0.5`, `z + 0.5`).
14. **`Creature`** : un mauvais argument (vitesse hors 0,3–2,5, composante de vitesse hors ±2, effet interdit…) ou
    une créature qui n'est plus à soi lève `ForgeRefusal` ; une créature partie (morte, déchargée) : le pilotage ne fait
    rien ; `info()` nul dans ces deux cas.
15. **`ModuleContext`** : après la fin (après le retour de `stop`), toute méthode lève `ForgeRefusal` ; pendant
    `stop`, les lectures marchent, les actes rendent `dropped`, minuteurs et abonnements sont refusés ;
    `tellDirector` garde la **dernière** note retenue et compte les autres ; `end` deux fois ne change rien.
16. **`Text`** appelle les sources du mod : `normalize` = `Answers.normalize` (la règle des quiz), `cut` =
    `ModelText.cut`, `duration` = `ToolText.duration` ; `words` découpe le texte normalisé sur les espaces. Ces appels
    ne sont pas mesurés par le compteur (ce n'est pas du code de module) : ils sont bornés par les tailles des textes
    (65 536 caractères).
17. **`Bench`** gagne `challenge(String... players)` (un défi jugé simulé, `ctx.game()` non nul, victoire notée dans
    `acts()`) et `restart()` (`SERVER_STOPPING`, instance neuve, `restarted()` vrai, même `Storage`) ; `check` est
    collant (un échec reste même si le scénario attrape ce qu'il lève).
18. **Pas de `pit` ni de `floor`** (décision Q4) : `Ground` n'a que `place`, testé (`ForgeContractsTest`).

### `forge/rt`

- **`Meter`** : `Meter(ClassLoader owner)`, `arm(budgetNanos, allocationBytes)`, `disarm()`, `tripped()`,
  `allocatedSinceArm()`, `enter()`, `exit()`, `tick()`. Contrat (Javadoc) **précisé** : `enter` **compte comme un
  `tick`** ; **hors d'un appel armé, `enter` et `tick` lèvent `ForgeLimit`** ; `tripped()` donne la cause et, quand
  elle est connue, la ligne du module (`time budget at TagGame.java:41`).
- **`ForgeLimit(message)`** : une `Error` qui garde sa pile (l'hôte en tire la ligne du premier cadre du module, puis
  lâche l'objet).
- **`Guarded`** : `array(int)int`, `capacity(int)int`, `text(String)String`, `add`, `put`, `append` (forme « vérifier
  puis rendre » ou « à la place de ») ; la Javadoc liste tout ce que M5-04 doit couvrir, constats ci-dessous compris.
  M5-04 en possède la liste et les corps.

## Constats nouveaux sur le bac à sable (pour M5-03, M5-04, M5-18)

Mesurés sur ce JDK 25 (`Alloc.java`, un essai jetable dans le dossier de travail de l'agent : `ThreadMXBean`,
`-Xmx2g`) :

| Appel d'un module, en **un seul** appel du JDK | Alloué |
|---|---|
| `new HashMap<>(20_000_000)` | 4,5 Kio (le constructeur est paresseux) |
| `new HashMap<>(20_000_000).put(1, 1)` | **134 Mo** (toute la table au premier `put`) |
| `HashMap.newHashMap(n).put`, `new LinkedHashMap<>(n).put`, `new HashSet<>(n).add`, `new LinkedHashSet<>(n).add` | **134 Mo** chacun |
| `new StringBuilder().repeat('x', 20_000_000)` | 20 Mo |
| `"a".indent(20_000_000)` | 120 Mo |
| `list.toString()` d'une liste de 1 000 textes de 65 536 caractères | **200 Mo** |
| `"" + list`, même liste | 200 Mo |
| `String.join("", list)`, même liste | 65 Mo |

1. **Le constat 1 de la relecture était incomplet** : elle disait `HashMap(int)` et `LinkedHashMap(int)` paresseux,
   donc libres ; c'est vrai du constructeur, pas du premier `put`. À 500 millions : 2 Gio d'un coup, à travers les cinq
   barrières. Les constructeurs à capacité des quatre tables de hachage **et leurs fabriques statiques** (`newHashMap`,
   `newLinkedHashMap`, `newHashSet`, `newLinkedHashSet`, JDK 19+) doivent passer par `Guarded.capacity`.
2. **`StringBuilder.repeat(int, int)` et `repeat(CharSequence, int)`** (JDK 21) et **`String.indent(int)`** sont des
   portes d'allocation en un appel (à envelopper ou refuser).
3. **Le texte d'une collection entière** a une taille égale au **produit** des limites (10 000 éléments × 65 536
   caractères = 655 millions de caractères) : `toString` d'une collection, d'une map ou d'un tableau,
   `String.valueOf(Object)`, `Objects.toString`, `StringBuilder.append(Object)`, **les arguments objets d'une
   concaténation** (`"Scores : " + map`), `String.join`, `Collectors.joining`, `Arrays.toString`/`deepToString`. Seuls
   les textes déjà bornés n'appellent aucun code du module : le compteur ne voit rien. À borner au site d'appel (M5-04 :
   un `Guarded.str(Object)` qui construit le texte d'une collection du JDK dans une limite, par exemple).
4. **Un `CharSequence` du module** peut annoncer n'importe quelle longueur : `StringBuilder(CharSequence)`,
   `append(CharSequence)`, `append(CharSequence, int, int)`, `insert(int, CharSequence…)` réservent `length()` d'un coup
   (déjà dans la liste du design pour le constructeur ; aussi pour `append` et `insert`).
5. **`Meter.enter` doit compter comme un `tick`** : une lambda du module qu'une boucle du JDK appelle
   (`IntStream.range(0, 65_536).boxed().flatMap(i -> …)`) n'a aucun saut arrière ; si `enter` ne regarde ni l'horloge
   ni l'allocation, rien ne l'arrête. Le prototype faisait `tick()` dans `enter()` ; le §3.4 ne le disait pas.
6. **Aucun code de module hors d'un appel armé** : le `Meter` désarmé lève. C'est la défense en profondeur du constat 8
   : un `hashCode` de module appelé par erreur hors invocation (une clé de map de l'hôte, un log) échoue au lieu de
   geler le thread serveur. Conséquence pour M5-05 : la jauge de mémoire ne doit appeler aucune méthode d'un objet du
   module (`size()` d'une `List` que le module implémente) hors d'un appel armé.

`M5.md` §3.3, §3.4 et §16.2 sont corrigés en conséquence.

## Les autres contrats

### Kotlin (`forge/Forge.kt`, §11)

- **`ForgeRejected(rule, message, failed = false)`** et **`MechanicRejected(rule, message, failed = false)`** :
  `toResult()` rend `DENIED (rule): …`, `FAILED: …` ou `Invalid arguments: …` ; `failed` et `rule` ensemble sont
  refusés. Le design voulait `FAILED: … no longer compiles`, `FAILED: C-70 failed to start: …`, `FAILED: the compilation
  took too long` : la paire `(rule, message)` ne savait pas le dire.
- `Forge` : `available`, `unavailableReason`, `arsenal`, `test`, `save`, `build`, `review`, **`status(): ForgeStatus`**
  (`ecj`, `compiler` : `idle`, `compiling statues (2s)`, `stuck since 21:04:10`), `stop()` (une seconde au plus).
- `Arsenal` : `list()`, `entry(name, version = null)`, `source(name, version)`, **`file(name, version): Path?`** (le
  chemin d'une version forgée, pour `/narrator forge show`).
- `ArsenalEntry` gagne **`classes`** et **`bytes`** (ceux du manifeste du §6.1 ; 0 tant qu'elle n'est pas
  construite) ; une entrée de départ : version 0, `savedAt = Instant.EPOCH`, `by = "built-in"`, `note = null`.
- `ModuleStatus.id` (`ready`…). `ParamSpec(min, max)` nuls quand `@Param` les laissait infinis, `fallback` nul pour
  `""`.
- `Built(entry, mainClass, classes)` : `classes` = nom binaire → octets réécrits (`OrbitingChickens`,
  `OrbitingChickens$Phase`, `OrbitingChickens$-meter`) ; **`Built.meterHolder`**, `Built.METER_SUFFIX` (`$-meter`),
  `Built.METER_FIELD` (`m`) : le contrat entre la réécriture (M5-04) et l'hôte (M5-05).
- `DisabledForge(reason)` : `ForgeRejected("forge_off", "the Forge is unavailable: <reason>")` partout, arsenal vide,
  `status() = ForgeStatus(null, "off")`. `DisabledForge.FORGE_OFF` est aussi la règle du coupe-circuit.

### Les modules déployés (`mechanics/Mechanics.kt`)

- **`ModuleControl.halted: ForgeHalt?`** (le design disait `String?` : `/narrator forge status` montre aussi qui et
