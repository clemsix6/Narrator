## Les lignes du moteur (§3.3)

Vérifié dans le travail d'écriture, avec les autres règles par auteur :

- **`addCanon` avec `mechanic`** : seulement `Source.DIRECTOR` (les outils du moteur écrivent comme le Directeur),
  sorte dans `CanonMechanic.kinds`, **sans `dueAt`**. Messages :
  - `only the engine's tools (start_challenge, propose_duel, create_rule) write a row the engine tracks` ;
  - `mechanic rule goes with a law or a plan, not a challenge` ;
  - `a row the engine tracks has no due time: the engine holds its end`.
- **`plan` sans `mechanic = rule`** : `a plan exists only as a rule the engine runs: create it with create_rule`.
- **`resolveCanon`** d'une ligne dont `mechanic` n'est pas nul : seulement `Source.ENGINE` ou `Source.OPERATOR`, sinon
  `C-50 is a challenge the engine tracks: end it with end_challenge` (`… a law/plan … remove_rule`, d'après
  `CanonMechanic.endedBy`). Le refus « déjà fermée » passe avant (plus utile).
- **Ajout : `archive`** d'une ligne du moteur encore ouverte est refusé (`C-50 is a challenge the engine tracks,
  still active: end it first (/narrator challenge cancel or rule remove)`). Raison : la réconciliation (§4.6) lit
  `canon(CanonFilter(open = true))`, qui exclut les lignes archivées ; une ligne archivée ouverte ferait retirer
  l'état au prochain démarrage sans jamais résoudre le canon. Une fois fermée, elle s'archive.
- **Doublons du canon** : une ligne avec `mechanic` n'est **jamais** comparée (deux défis identiques font deux
  lignes). En revanche, ce qu'un autre écrit sans `mechanic` (le Chroniqueur qui recopie un défi annoncé, le
  Directeur moteur éteint) **peut** être le doublon d'une ligne du moteur : `Added.Duplicate` de la ligne du
  moteur, ce qui évite un deuxième défi ou une deuxième loi au canon. C'est voulu.

## Les interactions du moteur (constat 12)

`Dedup.interaction` : une interaction est « du moteur sans preuve » quand sa source est `engine` et qu'elle n'a ni
`evidence_events` ni `tool_calls` (résultat d'un défi, enjeu payé, `punish` d'une règle). **Dès que l'une des deux
interactions comparées l'est, elles ne sont la même que pour le même `canon_id`** (non nul), même joueur, même
sorte, dans la fenêtre de ±10 min de M3. Entre toutes les autres, la règle de M3 reste (preuve commune, ou l'une
sans preuve, ou texte à 0,6).

Conséquences, testées :
- deux défis gagnés à cinq minutes d'écart : deux `challenge_result` ; le même résultat réécrit : `Duplicate` ;
- une interaction du moteur sans canon : jamais un doublon ;
- **la couverture d'un châtiment du Directeur** (`Sanctions`, `ENGINE` avec appels d'outils) **n'est pas avalée**
  par la pénalité d'un défi notée quelques minutes avant ; une note du Directeur sans preuve ne l'est pas non plus.

Prix accepté : si le Directeur note lui-même `challenge_result` après un `CHALLENGE` (sans preuve, sans canon : `note_interaction` n'a pas de canon), sa note n'est pas fusionnée avec celle du moteur. Le prompt (M4-22) doit dire que le moteur note lui-même les résultats et les enjeux.

La fenêtre de ±10 min est gardée : sans elle, la deuxième faute punie par une même loi sur le même joueur (même
canon, même sorte) serait avalée ; les délais de catégorie (10 à 60 min selon le chaos) les espacent déjà.

## Les récits (§10)

- **Thème** : `CanonDraft.theme`, exigé pour **tout** récit (`planned` du Rêveur compris), un slug
  `MemoryLimits.THEME` ; interdit aux autres sortes. Messages : `an arc needs its theme: a slug that names what it is
  about, like vengeance_du_warden`, `theme must be a slug of 2 to 40 lowercase letters, digits and _, like
  vengeance_du_warden (got "…")`, `theme only goes with an arc: leave it out`. L'outil rogne et met en minuscules.
- **Ajout : un thème est tenu tant que son récit est ouvert** (`planned` ou `active`) : `the theme « x » is C-60's, an
  arc still active: pick another`. Deux récits ouverts sur un même thème seraient un doublon.
- **Jachère** : le dernier récit fermé (`resolved_at`) d'un thème le fait reposer `THEME_REST_PLAY_HOURS` (20) heures
  **de jeu du monde**, comptées sur `sessions` par `DuckPlayClock.unionSeconds` (les sessions ouvertes comptent
  jusqu'à maintenant : le Journal ferme à l'ouverture celles d'un plantage). Message : `the theme
  « vengeance_du_warden » rests until about 10-02 15:40 (15h00m of world play left: a theme rests 20h of play once its
  arc is closed, and C-60 closed 10-01 19:40); pick another`. L'heure est une estimation si le jeu continue. Les
  récits archivés ne comptent pas (un opérateur peut libérer un thème).
- **Deux actifs au plus** : un troisième `addCanon` actif, ou `resolve … active` d'un récit prévu, lève
  `MemoryRejected(rule = "arc_limit")` : `DENIED (arc_limit): 2 arcs are active (C-60, C-71); resolve or abandon one
  first`. Les récits prévus ne comptent pas. Les doublons sont cherchés **avant** ces contrôles (un récit déjà
  enregistré répond `already remembered`, pas un refus).
- **Fin programmée** : un récit actif a toujours `due_at` ≤ maintenant + 7 jours :
  - créé actif sans échéance : + 7 jours ; au-delà de 7 jours : refus (`an active arc ends within 7 days:
    due_in_minutes 10080 at most`, inatteignable par l'outil, dont la borne est 10 080) ;
  - prévu puis démarré : son échéance si elle est dans les 7 jours à venir, sinon + 7 jours ;
  - un récit prévu garde l'échéance qu'on lui donne (le `DUE` ne part que pour les lignes actives, `JobsData`).
  Le `DUE` de M3 réveille ensuite le Directeur ; un récit n'expire pas (`ARC` n'a pas `expired`).
